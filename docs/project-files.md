# Project Files

This note is the format reference for project metadata. Code locations and
ownership are mapped in [Project Metadata Flow](project-metadata-flow.md).

## Prolfile.toml

`Prolfile.toml` is the user-authored project manifest. The format version is
required so newer format changes can fail clearly on older `prolm` binaries.

```toml
[meta]
prolfile_version = 1
min_prolm_version = "0.1.0"

[package]
name = "my-expert-system"
version = "0.1.0"
description = "A diagnostic expert system"
authors = ["Ada Lovelace <ada@example.com>"]
license = "MIT"
homepage = "https://github.com/ada/my-expert-system"
entry = "src/main.pl"
runtime = "swi"

[dependencies]
aop = "^0.0.9"
prosqlite = "^0.9"

[dev-dependencies]
plunit = "*"

[runtime.swi]
min_version = "9.0"
flags = ["-O", "--stack-limit=2g"]

[scripts]
start = "prolm run src/main.pl"
diagnose = "prolm run src/diagnose.pl -- --mode interactive"
```

When `prolm` writes the manifest, sections stay in this order:
`[meta]`, `[package]`, `[dependencies]`, `[dev-dependencies]`,
`[runtime.*]`, `[scripts]`. Keep keys deterministic so dependency changes do
not produce noisy diffs. Comments should be preserved where reasonable; if a
writer cannot preserve them, document that behavior before expanding its use.

## Constraints

| Syntax | Meaning |
| --- | --- |
| `"^1.4"` | `>=1.4.0, <2.0.0` |
| `"~1.4.2"` | `>=1.4.2, <1.5.0` |
| `">=1.4"` | at least `1.4` |
| `"=1.4.3"` | exact pin |
| `"*"` | any version |
| `"1.4.3"` | compatible range starting at `1.4.3` |

Use `github.com/Masterminds/semver/v3` for constraint handling. Do not invent
comparison behavior for prereleases, build metadata, `v`-prefixed tags, or
zero-major versions.

## Prolfile.lock

`Prolfile.lock` is generated metadata. Commit it, do not edit it by hand, and
keep it deterministic.

```toml
# This file is auto-generated by prolm. Do not edit by hand.

[meta]
lock_version = 1
prolfile_hash = "sha256:e3b0c442..."

[[package]]
name = "aop"
version = "0.0.9"
source = "swi-pack-index"
url = "https://..."
checksum = "sha256:a3f2c1d9..."
dependencies = ["http@7.1.2"]
```

Lockfile rules:

- The lockfile is the install source of truth once package selections exist.
  Manifest dependency changes drive add, remove, update, and stale-lock
  detection.
- `prolfile_hash` hashes dependency and dev-dependency inputs. Do not use file
  mtimes for staleness decisions.
- `[[package]]` entries are sorted by name. Keys keep the fixed order `name`,
  `version`, `source`, `url`, `checksum`, `dependencies`.
- Empty locks omit package entries instead of emitting `package = []`.
- Checksums use the explicit `sha256:<hex>` form.
- Preserve forward compatibility by adding fields instead of removing fields.
- Install order must be deterministic: topological dependency order with
  alphabetical tie-breaking.

Security-sensitive lockfile behavior is defined in [Security Rules](security.md).
